# 39条主进程终止分支的范围处置

已将既有源码合同确认的33条直接结束分支、6条不支持错误分支，正式登记为所选接收器的保留机制。该决定对应原计划2.1／2.2，缩减的是待作“功能或机制决定”的来源队列。

当前[来源清单v33](legacy-entry-dispositions-v33.json)和[队列v17](retained-entry-backlog-v17.json)保留全部968条来源身份。709条未关联具体功能的来源中，明确机制由141增至180，仍需决定的来源由568降至529。其余929条来源记录完全不变，全部功能关联、模式和运行状态保持。

处置范围只有选定的MMe.handleMessage。比如quit-app在这个接收器中直接结束，不能据此删除其他退出入口；六个不支持标签也不能证明整个产品没有相应设置、编辑器或WSL功能。已核对的前置avatar-overlay委托不匹配这39个固定字符串标签；稳定字符串与标准内建行为等既有假设继续适用。

本批采用已有语义结论，未新增源码解析或执行。509项功能、582个不同操作、1844条未执行场景、51项任务和505 unknown／4 shared模式计数保持；没有新增行为通过、模式排除或客户端实现。20个命令消费者缺口保持，host处理分支中尚未关联功能的待决定项为102条。
