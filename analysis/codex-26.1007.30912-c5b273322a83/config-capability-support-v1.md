# 模型、配置与能力支撑合同

本批明确20条现有来源的用途。969来源中700暂无用户功能映射，含238明确机制和462待用途决定；后者从482减少20。原525功能、603操作、1912条未执行规格、模式及两张实施依赖图保持。

隐藏模型目录和API-key实验能力查询用于Age偏好/availability，不凭RPC名关联模型选择UI。保存有会话、代次、host认证、user配置层及版本检查；线程设置、用户默认配置、预热线程和元数据分别更新，后续失败可能留下部分改动，不能整体视为回滚。

实验enablement按连接与policy generation同步，压缩支链独立完成。工作区依赖入口区分直接能力查询与按host缓存Promise，失败删除缓存。启动阶段另外保留policy检查、重启参数和settingsStore配置写入三种端口用途。

runtime MCP配置按连接串行；生成时明确排除私有进程环境。Qc只改已存在且内容不同的插件.mcp.json，临时文件rename后再请求配置重载，两个阶段无统一回滚。旧remote_control清理由独立迁移处理。MF的内测插件下载重载与用户重启MCP服务保持不同合同。

文件夹信任按未设置/显式untrusted分组提示，此处只可能把未设置组写成trusted，保留配置版本与覆盖错误。Chronicle开关保留pending/denied结果、顺序补偿及AggregateError，不假定补偿必然成功。

16项事实、51个来源单元、32个独立声明解析及16项源码检查通过；发布文件和原清单还需最终回读。五项职责路径是维护设计提案，不是已生成客户端。第三方实现仍以既有依赖/运行时边界引入。

本批没有模型/服务调用、客户端启动、目标求值、客户端实现或新增运行通过。有效账户/开关、服务接受、持久化与独立构建仍待验证。
