53 条旧 `settings-lexical-candidates` 均以固定 sourcePath、sourceHash、原字节范围唯一包含关系对应 `ua` 的完整属性。每项保存 property、字段 provider 的实际词法 binding、导入/定义坐标和旧 ledger witness。`component/commandAsset/navigation` 及 `la(e,t)` getter 支持“展示资产配置”的解释；未证明它们与页面表存在直接 consumer dataflow，不能把 53 项写成 53 个功能。

完整 app-initial Program 证实同一模块 `gWa` binding：51 项赋值 → `wnt` export → settings 的 `Rr` import → `_a` 内 `Rr.map` → 实际 `Tt` dispatcher。另一路同 `gWa` → 旧 ROUTE-0152 filter/map → `M6({slug})` → 同 Program `lQa[n]` binding。`lQa` 保存 53 项 factory 构造；53 资产、53 factory、51 section、50 路由是四个不同分母。`family`、`environments` 的 factory/case 存在不等于新增 route 或功能。

保存所有 53 个 visibility case，包括 fall-through、pending/error 语义，并为 51 个实际 section 建立 slug 数据流支持的 case 关联。保留 authMethod、capability/config、loading、第二参数 Ca allowlist、Ta→He family label、appshots/windows 资产分支。实际账户、host、模式与 predicate 值未观察；源码出现 ChatGPT 名称或 label 不能构成排除证明。
