# 完整文件读取后台契约

已补齐 FSC-0493 文件变更查看中原先未知的 `cat-file` 后台：renderer 的有序旧／新侧请求，经既有 Git worker 通道交给 `qAe`，再进入仓库、快照、Git 对象和条件磁盘读取。此处确认的是固定基线中的静态调用与结果契约，尚未执行 I/O 或客户端行为测试。

工程拆分保留三层：现有 CROP-M02/T09 负责页面、每文件状态、批次和部分／完整差异选择；共享 Git worker 负责对象读取与条件文件回退；主机、仓库快照、进程及第三方渲染依赖通过明确接口接入。读取适配与现有补丁应用／撤销适配分别维护，不复制第三方实现。

| 边界 | 已确认的基线行为 |
| --- | --- |
| 请求与结果 | 每批最多 4 个请求；对象 ID 去重读取后按原请求次序返回。外层 `ok` 内仍可有逐项 `not-found`、`too-large`、`unknown`。 |
| 容量与 Git | 数值参数按表达式限制在 0–5 MiB，缺省 5 MiB；`git cat-file --batch` 使用 30 秒超时和 `GIT_NO_LAZY_FETCH=1`，保留字节缓冲及输出截断后的尾部重试。 |
| 磁盘回退 | 旧侧禁用；新侧必须允许回退，且对象结果为 `not-found`。超限及未知错误不回退。路径基于所选 host 的仓库 root，与批注根目录分别维护。 |
| 文件流 | 先 stat，再至多读取限额加 1 字节；超限返回 `too-large`，释放流锁。可选快照通过 `read` 包装读取。 |
| 取消 | worker 支持提前／在途取消，Git 路径传入 signal；选定 renderer 调用没有传 signal，磁盘分支也没有接收它。关闭文件不等于取消后台读取。 |
| 内容接受 | 成功读取后仍需完整内容 metadata 一致性验证；读取成功、metadata 被接受、完整 diff 已显示是不同观察点。 |

此前 FILE-CHANGE-CONTRACT-027 的后台未知项现由本契约补充。保留未知项：实际信任判定、有效 host／worker／仓库／快照实例及 I/O 效果，独立 `/diff` 页状态生产者和产品模式。不会因此删除功能，也不把具名外部依赖继续展开成完成此模块的前提。
