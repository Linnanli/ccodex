# Codex 独立客户端恢复实施计划草案 版本 7

目标是恢复基线版本 Codex 模式的完整行为，剥离有证据证明仅供 ChatGPT 使用的功能，并以独立依赖引入第三方组件。最终项目须可维护、升级、从干净环境构建和打包，运行时无需读取原客户端安装目录。当前仍处于分析与行为核对阶段。

基线为 `codex-26.1007.30912-c5b273322a83`，版本 `26.1007.30912`、构建 `20156`。本版取代版本 6 的工作安排；旧快照保留。当前有限台账为 **103 项定义、107 项用户操作、27 项支撑机制、406 条待执行产品规格**。这些数量不代表完整客户端分母。968 条旧入口的全面功能映射、模式分类及真实产品验收仍待完成。

## 工程结构与源码恢复

按运行环境、状态所有权和生命周期生成第一方模块。REA 的图和 chunk 提供来源关系；AST 作用域、导入导出、状态写入及接收方决定可拆边界。跨文件循环、懒初始化和注册副作用必须显式保留。目录是维护设计，不要求还原原作者布局。

```text
apps/desktop/
  src/main/               启动、窗口、宿主服务、平台能力和退出
  src/preload/            世界隔离、消息桥、端口和浏览器注入
  src/renderer/app/       路由、模式、初始化、窗口级状态
  src/renderer/features/  各功能的界面、控制器和状态
  src/workers/            有独立生命周期的后台工作
  resources/              已登记来源的图标、本地化和其他资产
packages/
  contracts/src/          DTO、通知、错误、版本与能力合同
  desktop-transport/src/  IPC、MessagePort、分块、宿主选择和释放
  backend-adapter/src/    app-server及其他后台的独立协议适配
  runtime-adapter/src/    桌面能力接口和平台实现
  state-storage/src/      内存状态、持久化、迁移、退出保存
tools/
  recovery/               分析输入到第一方源码的可审查转换
  build/                  自有构建、类型生成、资源与打包工具
tests/fixtures/           合成目录、协议数据和行为场景
```

renderer 通过合同调用宿主，不导入 main 或原生实现。`sendRequest` 的不同接收方分别维护：app-server、桌面 HTTP、注入 resolver、扩展连接和协调 socket 不能合为一个协议。旧模块建议中 `app-server-client` 的职责归入 `backend-adapter`，`app-host-client` 的选择与传输职责归入 `desktop-transport`；接口和所有者保持独立。依据见[已有模块建议](module-boundary-proposals.json)、[app-host 职责](app-host-maintenance.json)和[进程边界](boundaries.json)。

每个恢复文件登记基线、原文件 hash 和范围、职责、运行环境、输入输出、状态所有者、初始化与清理、第三方边界及验收场景。源码生成先按绑定识别第三方范围，再转为包导入；混合 chunk 中的第一方 wrapper 留在对应业务模块。格式化和重命名不能补出原 TypeScript 类型、目录或源码历史。手工维护部分通过接口接入，重新提取先产差分，禁止覆盖已维护源码。

## 环境与扩展的新增边界

[环境与扩展合同](environment-extension-contracts.json)连接本地环境、Hooks、MCP 的具体页面与后端接口，形成 T14 至 T16 三组恢复任务。本版保留 35 个设置容器尚未完成操作归属的统计；这三组的新源码合同尚未计成正式功能定义。

- **T14 本地环境。** 分开项目选择、文件读取、编辑草稿、revision 冲突、保存和激活。文件保存成功后激活仍可能失败，应保留 `selection-failed`。工作树通过 Git 根目录设置，普通工作区使用自己的选择器；平台脚本、setup/cleanup/actions 与 TOML 编码属于第一方编排。真实宿主 `localEnvironments.saveConfig`、原子写入及执行脚本的消费者继续核对。
- **T15 Hooks。** 来源分组、项目根目录、路由选中、只读详情、启停与信任分别维护。受管理 hook 显示始终启用；未信任/变更后的 hook 先复核。写入 `hooks.state.<JSON 引号键>.enabled` 或 `trusted_hash`，设置 `reloadUserConfig: true`；`okOverridden` 必须转为覆盖层错误。列表无项目根时保持禁用，不使用公开后端的空目录默认值替代页面规则。
- **T16 MCP。** `manageOnly` 入口复用扩展管理器，初始 tab 为 MCP；共享 chunk 还包含插件、技能等逻辑，不能整块删除。新增/编辑/删除用 `config/batchWrite`，启停用 `config/value/write`；两者 `expectedVersion: null`，不同于环境文件 revision。OAuth 请求、外部浏览器打开、URL 缓存、完成事件和重启提示单独维护；项目来源的配置控件保留只读条件。

冻结客户端与公开候选的上述八类 schema 在 stable/experimental 两种导出中逐项比较，结果及 hash 见合同。它支持局部协议适配设计；真实 provider 的选择、服务效果、OAuth、配置耐久性及通知顺序仍需实际核对。隔离源码回放使用合成替身，产品验收规格保持未执行。

## 第三方与运行时处理

[依赖清单](dependencies.csv)保留 202 条记录。78 项根声明仅 6 项有根路径安装版本证据；新工程必须生成自己的精确锁。原版本来源事实、新工程候选版本和兼容结果分列。React/DOM、JSX/compiler/Scheduler、query/schema/UI primitives、Sentry 平台 SDK、capnweb、原生模块和 Wasm 均按接口引入；身份未确认时不猜包名、不复制内嵌实现。具体决定沿用[依赖引入表](dependency-import-decisions.json)与[内嵌依赖合同](embedded-dependency-contracts.json)。

运行时路线尚未选定。公共 Electron 42.3.0 实测不能直接满足 Owl 能力，需逐项处理任务管理器、更新策略、WebContents 所有权/clone/lease、网络和 IPC 权限。已有同 view 移动只证明该原语保留内存，不能作为完整 clone。objc-js 有局部独立构建候选，node-pty 有修改记录，实际目标 ABI 与平台行为各自验收。运行时取得与集成影响打包；合同、第一方状态机和恢复设计可以继续推进。

## 分析收束与实施顺序

每次调查以一个有关闭条件的决定为单位：完整功能处置、源码/状态/接收方映射、独立依赖路线或具体行为差异。已有合同及同一绑定不重复解析；只有新缺口会改变恢复决定时才扩大源码范围。

| 顺序 | 分析出口 | 后续实施里程碑 |
| --- | --- | --- |
| 1 | 保持来源、模式和共享依赖台账；把已定义功能与新发现入口逐组归属，完整分母待核实 | M1 建立独立工作区、构建、依赖和运行时能力接口 |
| 2 | 逐项处理运行时取得/替代、全部依赖、资源和构建输入，局部问题落到受影响功能 | M2 恢复 contracts、preload、传输、后台与存储适配 |
| 3 | 完成项目、普通创建/提交/流式/审批/取消/恢复的同链路对照 | M3 基础界面和状态；M4 任务生命周期 |
| 4 | 按 T01 至 T16 及剩余入口推进；云端、远程、终端、变更和系统能力继续加入覆盖表 | M5 恢复其余全部 Codex 能力 |
| 5 | 每个拟排除分支有模式与共享闭包证据；对齐完整恢复覆盖与实际验收 | M6 剥离、依赖审计和升级；M7 完整验收 |

当前 103 项定义均为模式 unknown，确认排除为 0。设置 accessFamily、账号类型或命名不足以证明 ChatGPT 专属。可先隔离候选分支和共享组件；实际删除以消费者及依赖闭包为条件。全部 968 旧入口、35 个待归属设置容器、12 项关联待办与跨功能快捷键重叠继续保留。[里程碑清单](implementation-milestones-v7.json)登记具体依赖与退出条件。

## 行为验收与升级

一次已授权桌面样例完成并可重新打开；后续两次授权均已使用，取消前任务提前结束，取消尚未验证；执行中停止并重启后原 turn 为 `interrupted`，没有自动续跑证明。剩余模型样例次数为 0。新增在线样例按具体场景另行授权，静态与离线验证继续推进。真实权限、账户和宿主条件在对应场景登记。

实现后按每项功能核对正常、失败、取消和重启结果。后台接受、模型完成、本地终态、界面导航与落盘分别观察。不能通过重发任务证明自动续跑，也不能用 mock 或内存保存代替完整验收。最终在干净环境构建并安装，确认所有状态、资源、原生组件和认证来源独立于原安装目录。

升级建立新基线，比较稳定功能标识、入口条件、协议、状态 schema、依赖修改、资源和平台行为，将差异映射到恢复模块与场景。数据变化须有迁移、备份和回退；混淆符号和 chunk 文件名只作该版定位。九项分析完成标准仍为四项资料/范围义务有交付、五项部分完成；本版补齐已定义功能的实施映射，完整分析和独立客户端尚未完成。
