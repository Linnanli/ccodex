# 默认 newTask 的拆分结论

`selectChat:true` 选择末尾的 Chat-kind 显示请求，并不直接代表整个客户端切换到 ChatGPT 模式。`Qx → VXt → wH` 的导入、导出和接收器已有分析，本次复用这些结果，仅补齐 `h7r → x7n → reveal` 的直接请求边界。

复刻时保留共享的任务草稿准备、项目上下文选择、焦点和导航守卫；将末尾的 Chat 显示目标拆为明确的 Codex 草稿显示适配。同时处理 newTask 快捷键中的模式切换变体。不能因为参数名含 Chat 删除整个函数，也不能让快捷键返回“已处理”却没有动作。

这是一项重建边界决策，尚未实现。直接把 `selectChat` 改为 false 是否等价，现有证据不足；下游 reveal 的实际副作用、命令最终获胜处理器和 gm 的运行值保留为未知，本批到此结束，不递归追查通用提供方。

`wH` 还会按显式模式、预填系统提示或 work 默认值分别处理模式，并存在导航准备失败、gm 提前返回、项目和草稿复用等分支。任务草稿准备仍区别于首轮提交，不能用模型 RPC 替换。

当前停滞的主要原因是分析范围反复扩展、重复维护台账、结论采用滞后。REA 首轮解析没有全局阻断，已有静态分析权限仍有效。模型样例剩余 0 只限制新增动态样例；尚未验证的行为应明确列出，不能成为无限扩展静态分析的理由。
