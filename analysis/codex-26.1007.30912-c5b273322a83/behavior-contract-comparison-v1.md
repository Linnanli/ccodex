# 已有行为记录与源码合同对照 v1

本批对照四条路径，使用已保存的自有合成样例与冻结源码合同。没有启动客户端、执行目标代码、提交模型任务或调用服务；离线核对不增加产品通过数。完整分析未完成。

| 路径 | 已有证据 | 尚未证明 |
| --- | --- | --- |
| 正常 | 首个样例同一 turn 的开始/完成事件、合成回复及 Node 直接读取 README 的工具输入记录；已完成历史经自有行导航恢复 | 普通 UI 到实际 provider/transport 的关联，其他能力与模式 |
| 失败 | 取消样例出现重连项，后来 UI 为 completed；模型称缺少直接文件工具 | 可归因的真实失败终态、错误 UI、未知交付后晚到结算 |
| 取消 | 提交一次，实际取消点击为 0；停止控件没有完成同 turn 运行状态绑定 | 点击到实际请求、同 turn 终态及清理后效 |
| 重启 | 运行中停止进程并重启后，经观察到的自有行打开同一 turn，显示 interrupted | 自动继续执行、SIGTERM 到 will-quit/flush 的因果、崩溃恢复策略 |

首个样例的 `exec` 是编排工具名。保存的三个输入审阅中，两条查询工具元数据，一条调用 Node `fs.readFile`；这些输入没有 shell 调用。该判断不外推为工具内部所有实现的进程审计。取消样例的 `completed` 只说明 turn 处理结束，不能视为文件读取目标达成。

提交后的早期 false、旧 decoder 找不到提示、重连文字和观察器超时均不能单独当作客户端失败。源码 `accepted` 不是完成事件，`outcome-unknown` 也不是后台取消。历史 34 个隔离场景使用了替身，不能补足真实取消点击。

重启恢复历史与恢复执行分别记录。本次运行中样例只观察到 `interrupted`；没有发送继续提示或 resume RPC，也没有观察到继续产生工具结果。正常已完成样例的历史恢复不能推广到执行中恢复。

三次获批模型提交已经用完。旧干预报告的“剩余 1”是最后一次停止/重启样例之前的历史快照，当前剩余 0。这个限制只约束新模型样例，不阻碍本批离线对照或其他已授权源码分析。

本批列出七个确切观察缺口及前置条件。失败、取消和自动继续执行都需要新的受控运行证据；仅有离线校验无法关闭。后续若使用替身，也只能验证适配器，不能据此宣称真实客户端或服务通过。
