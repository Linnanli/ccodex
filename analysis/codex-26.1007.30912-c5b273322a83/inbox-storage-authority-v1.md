# 收件项与计划任务已读状态的存储边界

本批将既有 FSC-0434 / AUT-M03 的 renderer 合同连接到选定主进程工厂、接收器和 SQLite 写接口。[结构化契约](inbox-storage-authority-v1.json)保存源码、SQL、12项事实和12条未执行补充场景。

关键发现是 `inbox-items-create` 的后端实际更新已有 `automation_runs`，没有在选定路径插入普通收件项。它按线程更新标题、摘要、状态和时间；不存在目标时不生成新行。

单项已读按线程及账户/用户/安装标识筛选。批量已读还要求原值为空、状态属于三个指定值，并满足 `updated_at <= readAt`。renderer 的乐观缓存修改不含相同截止条件，且没有在选定回调等待数据库确认或回滚，因此缓存清零不能当作已落盘。

选定工厂将同一 manager 传到消息处理器，并把成功变更通知发向所有窗口。代码到达 `better-sqlite3` 12.11.1 的明确边界；路径为 home / sqlite / 构建条件选出的 codex.db 或 codex-dev.db。实际 home 未读取。q 在 Electron 环境外返回空存储；独立原生构建、迁移和耐久性未验证。

恢复工程可据此将 main 消息适配与 SQL store 分开，renderer 的 AUT-M03 继续负责历史和缓存。第三方实现通过依赖引入。源码中的 `identity.kind===chatgpt` 是某个完成监听器的身份条件，本批不将它当作产品模式排除依据。

本批核对6次完整Program解析结果（2个不同JS文件）、选定绑定、构造器第17个参数、CJS getter导出、字节范围和字面SQL，并复核已有renderer与包元数据。未执行目标代码、客户端、模型、服务或数据库。首次资格脚本因局部变量与CommonJS的exports重名而在启动前失败，修正后通过；失败草稿已保留。

功能、场景、任务及来源处置清单版本保持；本批是一个新的写侧存储边界补充。505项模式未知、主要行为验证及独立构建缺口仍在，完整分析未完成。
