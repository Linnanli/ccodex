# 模式初始化与直接消费者：限定结论

本批关闭一个具名初始化调用方及其参数来源，不生成新功能账本或实施计划。

根组件 GPc 将 `z5?aHa:undefined` 交给 Gkc，再由其初始化闭包调用 Rkc。`z5=Nd()` 精确连接 shared 的 fIt/lW，判断的是 `/avatar-overlay` 窗口（含 initialRoute 参数），不是 Codex/ChatGPT 模式。七个排除键不含 `home-composer-mode-v1`，不能用该窗口条件制定模式剥离规则。

Gkc 的 `pending/enabled/disabled` 是持久化 hydration/写权限状态。产品模式另由瞬态值、持久值、能力与策略计算；`codex/work_tab/chatgpt` 标签还依赖 detail level，不能简单用 `work/chat` 一一映射。

`pss` 虽含 ChatGPT 项目文案，也有启动本地 Codex 任务的分支。应按入口和条件保留其职责；现有证据不支持按名称删除整个组件。`ces` 的 draft 强制 work 是消费端选择，不是已证明的持久化写入。

源码范围、哈希、六条精确导入导出连接及一个有界表达式语法核对通过。这些检查未执行目标代码，也不证明 React 挂载、真实权限、超时、服务后效或耐久性。静态事实与全部定位见[结构化证据](mode-bootstrap-consumer-v1.json)。
