# 实时语音的模式归属与保留边界

FSC-0466「发起和控制实时语音会话」从 `unknown` 改为 `shared`，是源码归属结论。Codex 与 ChatGPT 输入框通过明确的导入导出联接使用同一个 Aaa 启动函数；两个 Codex 首页消费者还直接传入 `codex`。移除 ChatGPT 模式时必须保留共享语音启动、会话、音频和控制接口。

| 消费者 | 源码条件与处理 |
| --- | --- |
| Codex/Work 输入框 Qft | `rn ? work : codex`；只在 home/页面伴随与新输入框条件下提供启动回调；保留 Codex 分支 |
| ChatGPT/Work 输入框 Wjt | `Bt ? work : chatgpt`；另受能力/浮层/home 条件控制；分离 ChatGPT 调用分支，不能删除共享函数或整个混合文件 |
| Codex 首页 Y、kt | 直接传入 `codex`，保留账户、公告资格与回调存在条件 |
| 参数化公告 xt、O | `work_tab` 或调用方 entryPoint 决定参数；保持条件，不做整模块排除 |
| avatar 控制器 pf | 保留能力、配置、媒体、工作区、会话状态、取消代次与转移条件；线程意图由 source/locator 选择 |
| 命令 Cfc、kfc | 保留活动会话停止、fallback 启动、静音/结束各自条件；原生快捷键与实际控制后效另验 |

## 统计标签不能代替模式判断

Codex 首页的显式 `codex` 语音调用旁，统计字段仍写着 `productExperience: chat`。头像控制器把 chat/work/codex 映射为枚举后，所选启动回调中的该局部变量只有两处词法引用，均传给启动统计类 Fq/xs。请求中的原 productExperience 还在转移时继续携带。这些事实不能单独证明产品路由，也不能用来误删 Codex 功能。

上游 Aaa 的产品参数还参与 Work 策略门槛、entryPoint 和请求构造，因此不能宣称全链路的产品字段都只是统计。Aaa 先经过能力和策略判断，还受 Bia 状态门控制；Bia 的 bf/Aia 中间实现本批未展开，保留它决定是否直接调用 bna 的条件。bna 记录启动身份并请求实时运行时。头像控制器根据请求来源与 locator 选择线程意图、准备麦克风、传递权限/协作/记忆上下文并调用会话接口；不会因为本批确认共享就取消这些条件。

## 维护与验证

复用现有 RCGA-M02 职责与 v12 实施方案，区分产品入口适配、启动状态/策略、线程/会话控制、音频适配和统计消费者。音频工作线程的 URL、消息、缓冲/静音和释放接口复用上一批音频合同。本批没有生成最终第三方实现副本，也不新增功能、操作、场景或职责编号。

6 个不同程序有完整 AST 抽取；最终保留 8 次原程序解析，修正前另一次草稿解析单列，8 条 ESM 联接与 475 处保存片段核对通过。计数中的重复解析不当作不同文件。14,770 个文件的字面量导入筛查只支持这组候选，不等于全局动态调用闭包。

有效模式变为 **503 unknown / 6 shared**，509 功能、582 不同操作、125 支撑、1844 未执行规格、115 职责、202 依赖保持。模式覆盖表 v8 优先于旧表及 v12 冻结快照中的模式计数；旧文件不覆盖。原九项分析要求、两张任务图与七项实施验收不变；AC-02/03/04/08 仍未完整满足，其余沿用已有记录/方案审查资格，本批没有重做全量验收。

没有新增客户端、音频、模型或服务运行。FSC-0466 三条既有场景只增加观察点，仍是未执行：需分别核实真实能力/账户/功能开关、运行时注册、麦克风/服务成功失败、取消/转移和系统快捷键等。已有任务完成或重启样例不能证明实时语音。
