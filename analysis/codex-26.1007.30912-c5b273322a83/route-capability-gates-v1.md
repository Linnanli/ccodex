# 路由能力条件与独立运行时保留决定

本批把已有 `oZ`/`tFs` 合同落实到135条路径记录，并核对170个路由构造和25处门控调用。它关闭的是这批路由的显式父子条件归属，不宣称完整功能范围、模式剥离或运行验证完成。

| 显式路由/父级条件 | 路径记录数 | 工程处理 |
| --- | ---: | --- |
| `chatgpt` 能力门控 | 34 | 保留条件和 seat-access 优先级；能力名称不直接等于当前产品模式。 |
| `chatgpt.conversations`，`allowWork=true` | 4 | 保留混合会话入口及真实许可来源，不能按 ChatGpt 页面名称整页删除。 |
| Work 访问状态 | 27 | 保留 loading/allowed/denied/error 及各自导航。 |
| 所选路由拓扑没有上述门控 | 70 | 继续检查页面内部条件；此项不代表无权限控制或必然属于 Codex。 |

`oZ` 的 seat-access 屏幕在 selected capability 拒绝前判定。`allowWork=true` 跳过这条屏幕和等待分支。门控没有直接读取 `isError` 或当前产品模式；不能凭错误状态自行生成额外页面。底层 config-feature 列表加载完成却未找到键时，`enabled !== false` 条件仍成立，不能擅改成默认拒绝。

对独立构建有直接影响的结论是：六条明确的 browser-use 设置路径（扩展、下载、历史、联系资料、密码、站点设置）没有被这个路由层的 `oZ` 包住。因此不能以“剥离 ChatGPT”作为删除 FSC-0221/RAM-15 的依据。`M6`/设置策略、主机和实际能力条件仍需各自证据；原生页面、partition、挂载/清理、导航和底层服务的完整要求继续保留。现有 stock Electron 差异和独立 Owl 来源缺口没有因本批消失。

建议现有 router/route-table 职责显式保存这些条件，把产品模式取舍与许可判断分别处理。现有两套60节点依赖图保持原样；新增八条未执行子规格用于门控回归，未加入产品通过数或新功能数。

这次只读冻结源码和保存合同，解析两个完整 shared Program及五个有界源码片段，核对四条显式 ESM 连接。基础门控语义早有结论，本次新增的是逐路由父级传播与浏览器设置保留决定。没有重开许可/账户提供方。

现有509功能、582不同操作、1844未执行规格和51任务保持。模式仍为505 unknown / 4 shared；没有新增整功能排除、运行时资格、客户端实现或构建通过。`qPs` 等页面内部也可能再包门控，本表的“没有”仅限显式路由拓扑。
