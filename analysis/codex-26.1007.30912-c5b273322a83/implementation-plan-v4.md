# Codex 独立客户端恢复实施计划草案 版本 4

目标是恢复固定版本 Codex 模式的完整行为，移除经证实的 ChatGPT 专属分支，并通过依赖管理引入第三方组件。最终客户端须能从干净环境构建、打包和升级，运行时无需读取原应用安装目录。本文安排恢复工作；当前授权范围仍是分析和行为核对，尚未开始客户端实现。

基线为 `codex-26.1007.30912-c5b273322a83`，应用版本 `26.1007.30912`、构建号 `20156`。机器可读的依赖、产物、验收和证据引用见[里程碑清单](implementation-milestones-v4.json)。[上一版](implementation-plan-v3.md)及其来源索引保留；当前计划选择由 `analysis-state.json` 的 `analysisMilestones` 指定。

## 当前可以决定的工程边界

源码按运行环境、状态所有权和生命周期组织。main、preload、renderer、worker 与外部后台服务分别维护；它们之间使用明确的请求、响应、通知及清理契约。发布 chunk 只用于来源定位。依据是[运行边界](boundaries.json)、[IPC 清单](ipc.json)、[局部模块建议](module-boundary-proposals.md)和[app host 职责](app-host-maintenance-summary.md)。

第三方实现通过包、独立运行时或可维护的补丁依赖引入。第一方业务封装单独保留。React、Sentry、capnweb 的公开版本是已有发行依据的候选；基线实际锁和完整兼容性尚未确认，不能把候选版本写成已证实的原安装版本。[依赖决定](dependency-import-decisions.md)与[依赖清单](dependencies.csv)分别保存采用条件和来源事实。

功能恢复从具体操作开始：入口及条件、参数、状态变化、外部接收方、错误与取消、重启后结果必须对应同一个场景。提交得到接受、任务完成、本地写入 interrupted 和后台停止执行分别验收。依据是[任务合同](thread-turn-feature-contracts-summary.md)、[通知状态](turn-notification-state-summary.md)与[中断控制流](interrupt-control-flow-summary.md)。

项目目录采用下面的职责布局。路径是维护设计建议，并非原作者目录的还原；每个实际生成文件还须登记原始哈希、范围和依赖归属。

```text
apps/desktop/
  main/                 窗口、宿主服务、应用生命周期
  preload/              世界隔离、消息与端口适配
  renderer/
    app/                路由、初始化、窗口级状态
    features/           项目、任务、审批、变更、终端、设置、连接
  workers/              有独立生命周期的后台工作
  resources/            有来源记录的图标、本地化和静态资源
packages/
  contracts/            跨进程请求、响应、通知和版本契约
  backend-adapter/      app-server 与其他已确认后台边界
  runtime-adapter/      桌面能力接口及平台实现
  state-storage/        状态、持久化、迁移与退出保存
tools/recovery/         第一方提取、转换、命名与来源映射
tests/fixtures/         合成项目、协议样例与行为场景
```

renderer 不直接导入 main、原生模块或文件系统实现。contracts 不拥有窗口和业务状态；backend-adapter 不接管界面路由；runtime-adapter 不包含第三方运行时的实现副本。业务状态与持久化分开：内存更新、广播、显式 flush、文件替换和退出清理具有不同失败边界。[存储来源](global-state-storage-origin-summary.md)、[持久化策略](main-persistence-policy-summary.md)与[退出合同](shutdown-persistence-summary.md)提供对应依据。

## 当前缺口如何影响实施

当前[有限功能视图](feature-scope-v5.json)有 46 项定义、50 个用户操作、21 个支撑条目和 3 个入口/协议关联待审候选；200 条功能验收规格未执行。原 71 个根候选保留，新增一个具体用户归档入口后为 72 根；拆分 WSL 容器后为 74 个行为条目。旧归档候选实际用于预热线程清理，另按支撑维护。原 12 项关联/集成待办全部保留；46 项模式 unknown、确认排除 0。42 项定义条件性关联到同一个旧设置路由容器，另 4 项旧入口身份待定；967 个旧入口未完成映射，完整功能分母未知。

| 决策 | 已有依据 | 仍影响实施的缺口 | 对工作的影响 |
| --- | --- | --- | --- |
| 功能保留与剥离 | [入口台账](functional-entry-ledger.json)、[模式分析](chatgpt-mode-boundary-summary.md) | 入口到功能映射、完整模式值域、共享调用闭包 | 可设计职责和场景；ChatGPT 分支删除须逐项取得证据 |
| 桌面运行时 | [运行时方案](runtime-adapter-options.md)、[取得来源](runtime-distribution-summary.md) | 独立 Owl 来源、私有 API、ABI 与升级渠道 | 可定义能力接口；运行时选择与独立打包仍有前置缺口 |
| 后台服务 | [协议比较](protocol-comparison.md)、[版本来源](app-server-version-origin-summary.md) | 实际 provider、预测字段和通知顺序差异、公开包到源码版本的关系 | 可建立协议适配边界；不能直接认定公开 app-server 完全兼容 |

## 分析阶段的收束顺序

| 里程碑 | 具体交付 | 达成条件 |
| --- | --- | --- |
| A1 功能范围与模式 | 将旧入口、71 个原始候选及新增归档入口、46 项定义及关联待办逐项对照；保留容器与分支、导航与展示的父子关系 | 每个已发现入口有保留、排除、支撑或待定记录；共享依赖有理由；功能分母及未解决项分别统计 |
| A2 运行时与依赖决定 | 每个所需第三方、私有、原生、Wasm 和辅助程序的来源、版本依据、引入方式；运行时能力逐项决定 | 独立构建所需输入可取得，或对应替代路线有契约与验证办法；不能取得的项明确影响哪些功能 |
| A3 关键链路与源码映射 | 为各保留功能建立入口到状态、receiver、存储和拟恢复模块的映射 | 已知缺口具体落到功能和接口，所需生命周期、失败及取消语义足以指导实现；动态关系有明确验证条件 |
| A4 行为对照与实施验收 | 正常、失败、取消、重启场景的实际记录；源码映射、阶段依赖和完整验收表 | 已执行与未执行分列，差异有解释或后续任务；原分析计划九项标准逐项复核后才能宣布分析完成 |

A1、A2 和 A3 按各自缺口推进，不要求先把所有 unknown 清零才能安排其他证据充分的模块。每次调查须关闭一个已列问题，或改变明确的实施决定；新线索进入对应里程碑。局部辅助函数只有在影响参数、状态、错误、依赖来源或平台行为时才继续深挖。来源完整性检查用于保护证据，不代替功能判断。

[操作归属审查](operation-queue-review-summary.md)将两项只读展示、四项通知状态和一项能力条件归为支撑机制。WSL 卡片拆出添加项目目标、连接导航和安装说明，原有关联及运行缺口仍单列。General 只发送打开弹窗消息并省略 `setActive`；保持请求的已分析路径中，主动项目切换要求严格 `true`，因此不能擅自补默认值。目录检查、缺失目录确认、创建 API 和旧状态写入分别保留，公共 bookkeeping 的真实效果继续核对。

[归档入口调查](thread-archive-entry-summary.md)已找到具体菜单和条件调用，纠正旧候选为预热清理，并用 19 个隔离源码场景核对失败和撤销顺序。UI 所选 RPC 与实际 manager 实例、存储和通知仍未连通验证；这批观察不算真实功能验收。恢复模块须分开处理菜单/确认、撤销历史、归档状态、缓存与预热生命周期，保留 pending 遗留和后台成功后本地失败的语义。

[resume 调查](thread-resume-entry-summary.md)已连接页面与按需恢复 hook，区分 UI resumeConversation、低层 resumeThread、并发恢复协调与显式 turn 提交。19个隔离场景通过；实际 RPC/manager 身份、完整 hydration、服务端行为及旧 API 到用户操作的等价关系仍保留。v5只更新候选调查状态，功能数和覆盖率不增加。

下一项 A1 调查追 `thread/fork` 的具体入口、参数、结果导航与原线程处理，并保留普通/MCP `thread/start` 的独立入口待办。归档和 resume 的页面入口不重复调查；它们的实际 provider、存储、通知、模式和行为缺口分别推进。调查交付必须改变一个实现决定或关闭明确问题，隔离观察继续与真实功能验收分列。

A2 同时保留运行时和依赖的独立取得缺口。需要新增模型任务的行为验证列在 A4，当前不重复提交。该审查没有增加已通过行为或完成的产品功能数。

## 生成源码和后续升级

每个第一方恢复模块保存 `baselineId`、原文件哈希及范围、转换规则、职责、运行环境、导入导出、副作用、依赖、拟议路径和验收场景。旧混淆符号只作来源定位，不用作跨版本稳定身份。第一轮先验证少量模块的提取与重新导入，再扩展到完整清单；恢复工具不将整个 chunk 输出为一个业务文件。

恢复输出与手工维护的适配器采用明确接口和可审查变更。重新运行转换前先比较输入哈希；出现来源变化或冲突时保留差分，不能覆盖维护者修改。第三方范围转为包导入，应用自己的 wrapper、初始化顺序和生命周期继续维护。包管理器生成独立项目锁，另存基线安装版本的证据，两者不混写。

升级时建立新基线，比较入口、协议、状态 schema、资源、依赖及平台行为，把差异映射到模块与场景。原项目的功能扩展通过模块和接口保留；数据格式变化附迁移、备份、旧版本重开和回退结果。升级验收仍覆盖新基线的完整 Codex 功能，不以 bundle 能启动代替。

## 行为验证的当前边界

已有合成样例证明一次桌面任务完成并可重新打开。后续两次授权均已使用：首条任务在取消操作前已完成，取消未测试；第二条执行中停止并重启后，同一任务可从实际侧栏行重新打开，状态为 `interrupted`，没有自动继续执行的证据。当前本组剩余额度为 0。[停止重启记录](behavior-stop-restart-summary.md)是该组当前状态；早期记录中的“剩余一次”仅是历史快照。

继续分析无需新增模型调用。新的模型样例只在确实需要补对应行为证据时另行取得授权；已用额度不限制静态源码分析。正常路径、失败、取消、审批、终端与实际持久化分别保留场景，使用独立应用和合成目录核对，避免接触个人历史和凭据。权限、账户和平台条件不满足的项保留在完整验收范围内。
