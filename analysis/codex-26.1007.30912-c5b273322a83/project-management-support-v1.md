# 项目、成员关系与线程分组支撑合同

本批明确24条旧来源的支撑用途，并登记旧文字调用清单漏出的1处动态project/create/import调用。当前969来源中700尚无用户功能映射，含218明确机制与482待用途决定；原968个ID保留。525功能、603操作、1912条未执行规格、模式和两张实施依赖图保持。

已定位SDMD-04选定源码提供方：主进程把AJe回调与projectsManager接到同一个NHe本地实例，NHe再交给DHe处理成员关系。此为源码注入证明，实际构造、有效开关、服务接受与磁盘完成仍待观察。

项目写入按项目排队，失败不阻塞下一次；元数据另有按host/home及项目身份的跨实例锁。创建与导入带legacy幂等键，更新保留既有metadata。排序逐次移动，失败没有全局回滚。项目删除先持久化待删除记录，60秒内满足原身份条件可恢复；到期才后台删除，失败至少30秒重试。断连停止timer，重连从记录恢复。

成员归属通常先更新后台metadata再执行本地回调，projectless编码为空字符串；两者不是整体事务。迁移每页100、每批8，批中部分成功后仍可能因其他项失败而抛出。refresh/adopt更新本地记录与通知，不自动代表文件flush。

置顶/自定义分组保留连接身份校验、按host排队及旧置顶迁移。创建后移动失败只做有条件的空分组补偿，分组被采用后不能删除。置顶set收到false与排序收到false的本地镜像行为不同，恢复时需保留；backend成功后的flush失败也不等于后台回滚。

建议分别维护项目协调、延迟删除、成员适配和分组服务四个职责。它们是带来源的设计提案，尚未生成客户端实现。通用本地项目层与ChatGPT关联字段/恢复分支共处，未按名字排除整类代码。Node、schema、锁、运行时及具名第一方引擎以依赖/端口边界保留。

18项事实、66个来源单元、25个独立声明解析和18项源码检查已核对。模型提交、客户端启动、服务调用及新增运行通过均为0。
